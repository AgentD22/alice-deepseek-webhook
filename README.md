## 📖 О проекте

Этот проект позволяет умной колонке **Яндекс Алиса** отвечать на вопросы пользователей, используя мощь нейросети **DeepSeek** вместо встроенных алгоритмов Яндекса.

Проще говоря — Алиса становится **намного умнее** 🚀

### Что умеет:

- 🗣️ Отвечать на вопросы через DeepSeek с учётом последних 10 пар реплик текущей сессии
- ⚡ Передавать запросы DeepSeek через webhook на Vercel
- 🔒 Хранить API-ключи в переменных окружения, а не в коде
- 🔄 Автоматически развёртываться при изменениях в подключённой ветке GitHub
- 📩 По явной просьбе отправлять в личный Telegram тот же ответ, который получает Алиса

> Webhook передаёт DeepSeek контекст последних **10 пар реплик** текущей сессии Алисы. Это краткосрочная память: новая сессия начинает диалог заново. Переписка хранится в `session_state` навыка Алисы, а не в отдельной базе данных.

## 🏗 Архитектура

```
┌─────────────┐     ┌─────────────────┐     ┌───────────────┐
│   🎤 Алиса   │────▶│  ☁️ Vercel       │────▶│  🧠 DeepSeek  │
│  (колонка)   │◀────│  (Webhook API)   │◀────│    (LLM API)  │
└─────────────┘     └────────┬────────┘     └───────────────┘
                             │
                             ├────▶ 📩 Telegram (личный чат)
                             │      только по просьбе пользователя
                             │
                    код хранится в GitHub;
                    push в GitHub запускает деплой Vercel
```

### Как это работает:

1. **Пользователь** задаёт вопрос Алисе. Если нужно получить копию ответа в Telegram, добавляет явную просьбу, например: «Объясни, что такое полярное сияние, и отправь мне ответ в Telegram».
2. **Алиса** отправляет запрос на webhook в Vercel.
3. **Vercel** распознаёт просьбу о пересылке и отделяет её от самого вопроса.
4. **DeepSeek** формирует ответ на вопрос.
5. **Vercel** возвращает ответ Алисе. Если пользователь попросил пересылку, тот же текст отправляется Telegram-ботом в заранее настроенный личный чат.
6. **Алиса** озвучивает ответ пользователю.

Отправка в Telegram не обязательна: без соответствующей просьбы ответ остаётся только в навыке Алисы.

### Контекст диалога и память

Webhook передаёт DeepSeek до **10 последних пар** «вопрос пользователя — ответ ассистента» из `session_state` Алисы. Благодаря этому можно задавать уточняющие вопросы вроде «А что насчёт его спутников?» — если нужные реплики всё ещё входят в сохранённую историю.

- Новая сессия Алисы начинает историю заново.
- В коде остаются максимум 20 сообщений (10 пользовательских реплик и 10 ответов); на каждый запрос DeepSeek получает эту историю вместе с новой репликой.
- Для экономии места каждый сохранённый текст ограничивается 1 500 символами.
- Это память только в пределах активной сессии навыка, не долговременное хранилище. Если нужен контекст между разными сессиями, потребуется внешняя база данных.
- Фактический объём состояния ограничивается платформой Алисы. Если история не помещается в состояние навыка, сократите количество/длину хранимых сообщений или перенесите историю во внешнее хранилище.
- Telegram-команда удаляется из пользовательского вопроса до обращения к DeepSeek; в историю записываются очищенный вопрос и ответ модели.

## ⚙️ Настройка

### Переменные окружения

Для облачного запуска добавьте переменные в Vercel: **Project → Settings → Environment Variables**. Локально можно использовать `.env`, но не добавляйте этот файл в Git — внесите его в `.gitignore`. Секретные значения не публикуйте в репозитории и не выводите в логи.

| Переменная | Назначение | Обязательность / пример |
|---|---|---|
| `DEEPSEEK_API_KEY` | API-ключ DeepSeek | Обязательна, `sk-...` |
| `SYSTEM_PROMPT` | Инструкция для DeepSeek | Необязательна, например `Ты — дружелюбный ассистент` |
| `TEXT_NOT_UNDERSTOOD` | Ответ на пустой или непонятный запрос | Необязательна |
| `TEXT_DEEPSEEK_ERROR` | Ответ при ошибке DeepSeek | Необязательна |
| `TEXT_GENERAL_ERROR` | Общий ответ при ошибке webhook | Необязательна |
| `TEXT_WELCOME` | Приветствие навыка | Необязательна |
| `TEXT_GOODBYE` | Ответ на команду выхода | Необязательна |
| `TEXT_HELP` | Ответ на команду помощи | Необязательна |
| `TELEGRAM_BOT_TOKEN` | Токен бота, созданного через `@BotFather` | Нужна для отправки в Telegram |
| `TELEGRAM_CHAT_ID` | Числовой ID вашего личного Telegram-чата с ботом | Нужна для отправки в Telegram |

### Развёртывание на Vercel

1. **Импортируйте проект** из GitHub в Vercel.
2. **Настройте переменные окружения** в Project → Settings → Environment Variables. Для Telegram добавьте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.
3. **Запустите деплой**. При подключённой интеграции последующие изменения выбранной ветки GitHub будут запускать новый деплой.

После деплоя ваш webhook будет доступен по адресу:

```
https://ваш-проект.vercel.app/api/webhook
```

### Подключение к Яндекс Алисе

1. Зайдите на [dialogs.yandex.ru](https://dialogs.yandex.ru)
2. Создайте новый **навык**
3. В настройках укажите:
   - **Тип backend**: Webhook
   - **Webhook URL**: `https://ваш-проект.vercel.app/api/webhook`
4. Пройдите модерацию
5. Опубликуйте навык и привяжите к колонке

### Настройка отправки ответа в личный Telegram

1. Создайте Telegram-бота через [@BotFather](https://t.me/BotFather) и скопируйте его токен.
2. Откройте личный чат с ботом и нажмите **Start**. Бот не может первым начать личную переписку.
3. Узнайте числовой ID личного чата. Например, после отправки боту сообщения можно запросить `getUpdates` у Telegram Bot API и посмотреть значение `message.chat.id`. Не публикуйте URL запроса: в нём содержится токен. Также можно использовать проверенный инструмент для получения ID.
4. Добавьте токен в Vercel как `TELEGRAM_BOT_TOKEN`, а ID личного чата — как `TELEGRAM_CHAT_ID`.
5. После сохранения переменных запустите новый деплой.

Пример команды Алисе:

> «Расскажи, почему небо голубое, и отправь мне ответ в Telegram»

Webhook удалит просьбу о пересылке из вопроса, получит ответ DeepSeek и отправит **тот же текст**, который вернёт Алисе. Если просьбы о пересылке нет, сообщение в Telegram не отправляется. Если Telegram временно недоступен, Алиса всё равно получит ответ.

`TELEGRAM_CHAT_ID` должен быть ID **личного чата с ботом**, а не обязательно ID пользователя из стороннего сервиса. Часто это один и тот же положительный числовой ID, но используйте именно `message.chat.id` из сообщения, полученного ботом.

## 🔧 Кастомизация

### Изменение системного промпта

Вы можете настроить поведение AI, изменив переменную `SYSTEM_PROMPT`:

```
# Дружелюбный помощник
SYSTEM_PROMPT = "Ты — дружелюбный голосовой ассистент. Отвечай кратко и по делу."

# Эксперт по cooking
SYSTEM_PROMPT = "Ты — шеф-повар с 20-летним опытом. Помогай с рецептами."

# Пират 🏴‍☠️
SYSTEM_PROMPT = "Ты — весёлый пират. Отвечай в пиратском стиле, матрос!"
```

### Параметры генерации

В текущем `webhook.py` заданы:

- Модель: `deepseek-chat`.
- `temperature: 0.7` — умеренная вариативность формулировок. Меньшее значение делает ответы более стабильными, большее — более разнообразными; это не настройка точности фактов.
- `max_tokens: 350` — верхний предел длины ответа модели в токенах, а не точное число слов или символов.

Модель и эти параметры сейчас указаны прямо в коде. Переменные `DEEPSEEK_MODEL`, `MAX_TOKENS` и `TEMPERATURE` сами по себе не используются. Для изменения отредактируйте соответствующие значения в `payload` и выполните новый деплой.

## 🐛 Решение проблем

| Проблема | Решение |
|---|---|
| Алиса не отвечает | Проверьте URL webhook в настройках навыка и логи функции в Vercel |
| DeepSeek возвращает ошибку | Проверьте `DEEPSEEK_API_KEY` и доступность API |
| Ответ не приходит в Telegram | Проверьте `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` и нажали ли вы **Start** в чате с ботом |
| Telegram отправляет не в личку | Убедитесь, что `TELEGRAM_CHAT_ID` взят из `message.chat.id` личного диалога с вашим ботом |
| Деплой не проходит | Проверьте логи в Vercel → Deployments |
| Переменные окружения не подхватились | Проверьте их имена и окружение Vercel, затем выполните новый деплой |
